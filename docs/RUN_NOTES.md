## 4. 実動画で見つかった問題と対処

### 4.1 圧縮ノイズを変化として拾っていた

静止したスライド上でも H.264 の量子化ノイズが 1〜2 画素単位で全画面に散り、
それを「小さな変化」として検出していました。合成テスト動画は可逆圧縮だったため表面化していません。

対処: 局所密度フィルタ（`ScanConfig.noise_density_window` / `min_local_density`）。
5x5 窓で 20% 以上が変化している画素だけを残します。文字の変化は塊になるため残り、
孤立したノイズ画素は落ちます。

### 4.2 保留中の小変化の一致判定が緩すぎた

`_region_consistent` が「範囲の面積の 5%」を許容していたため、広く散らばった変化に対して
許容量が過大になり、ノイズを「同じ変化が継続している」と誤判定していました。

対処: 許容量を「保留中の変化の画素数」基準に変更。

### 4.3 マウスポインタの移動（過剰分割の主因）

3 分で 87 状態も切り出された主因。変化の正体は最大輝度差 170 の高コントラストな
20〜27 画素の塊で、**常に大きさの揃った 2 つ**（消えた位置と現れた位置）でした。

対処: `_looks_like_pointer_move`。参照画像の一方の位置の見た目が現在画像のもう一方の位置に
現れていれば移動と判定し、視覚イベント（`event_kind='pointer'`）として記録して状態を作りません。
塊が 1 つだけの場合は 1 文字編集と区別できないため、移動とみなしません（設計 5.5）。

あわせて、画面最終列（x=959）に固定で出る符号化の端部アーティファクトを差分から除外
（`ScanConfig.border_margin_px`）。

結果: 3 分区間の表示状態が **87 → 39**。うち 16 個は 0.8 秒のクロスフェード遷移で、
正しく `transition` として VLM 対象外になっています。実際のスライド切り替えは 2 回。

### 4.4 設計 5.2 の第 2 段階が未実装だった

「変化した領域を原寸クロップで再認識し、前後の文字列を比較する」処理が抜けており、
すべての状態にいきなり全画面パスを走らせていました。

対処: `VisionExtractor.region_text_unchanged`。変化範囲が画面の 5% 以下なら、その領域だけを
前後 2 フレームで読み比べ、文字が同じなら前の本文を継承して全画面パスを省きます。
判定できない場合は None を返し、統合を保留して全画面パスへ進みます。

**この処理はまだ実動画で測定していません。**

### 4.5 VLM の設定

- `--image-min-tokens 1024`: llama.cpp が Qwen-VL について警告する下限。文字の読み取り精度に効く
- `crop_max_tokens = 1024`: クロップは 1 領域分しか転記しないので上限を絞り、
  繰り返しループに入ったときの損失時間を抑える
- `repeat_penalty = 1.05`: 同じ記号を延々と生成する退行を抑える
- `max_image_long_side = 1920`: 1080p を縮小しないことで、全本文領域が原寸再認識の
  対象になるのを避ける（縮小すると `crop_reread_all_body_when_downscaled` が発動していた）

**4.5 の変更もまだ実動画で測定していません。**

## 5. 残っている懸念

- **VLM の処理時間**: 4.4 / 4.5 の効果が未測定。全編を回す前に必ず 3 分区間で測ること
- **繰り返しループ**: `crop_max_tokens` で損失は約 1/4 に抑えたが、発生自体は残る。
  多発する場合は、文字が無いクロップを送らない判定を足す
- **領域の分類**: 合成テストではスライド本文が `terminal_output` と分類された。
  実動画での分類品質は未評価。見出し・箇条書きの構造が失われる場合は指示文の調整が要る
- **ASR の幻聴**: 非発話区間で whisper が文を生成することがある。無音区間なら確認項目に
  上がるが、トーンや雑音がある区間では上がらない

### この実行で見つけて直した不具合

1. **GPU ロックの生存確認が Windows で機能しない** — `os.kill(pid, 0)` は Windows の
   Python では `TerminateProcess` を呼ぶ。生存確認にならず、相手を終了させかねない。
   強制終了したプロセスの残留ロックを ASR が 1 時間待って失敗した。
2. **ASR の再開時データ損失** — チャンク完了をチェックポイントに記録する一方、発話は
   全チャンク終了後に保存していた。中断すると復元できない区間ができる。
3. **CPU 版 ASR が GPU ロックを取る** — GPU を使わないのに画像認識をブロックする。
4. **frame_scan の PNG 圧縮が過剰** — 代表フレーム候補 5 枚を毎回圧縮していた。
   選定後に 1 回だけにし、遷移状態（全体の 83%、VLM 対象外）は画像を保存しない。
5. **再開後の網羅情報が誤り** — その実行で処理した範囲しか反映せず、再開前を
   「表示状態を切り出せていない区間」と誤報告していた。
6. **Markdown が読めない大きさになる** — 未抽出の遷移状態ごとに節を立てて 61MB。
   連続する未抽出区間を 1 節にまとめて 3.0MB に。期間は JSONL に 1 件ずつ残る。
7. **未処理を「抽出失敗」と分類** — 中断時に未着手の期間が失敗として報告されていた。

### 未修正で残っている問題

- **管理下の llama-server が落ちても再起動しない**。9 時間ほどの連続稼働後に
  サーバーが落ち、以降の要求が接続エラーになった。3 回再試行するだけで先へ進む。
  長時間実行するなら自動再起動が要る。
- **4B の切り詰めが多い**。全画面パスの 46%（729/1,591）が出力長制限に達した。
  3 分区間の試験では 2 件だったので、動画の他の部分で繰り返し生成に入っている。
  切り詰めは成功扱いせず領域分割へフォールバックしているが、品質としては良くない。

### モデルの選定

8B と 4B を同一区間で比較し、**4B を採用**した（設計 16 の見直し条件に該当）。

| | 8B | 4B |
|---|---|---|
| vision 合計 | 291.9s | 69.5s |
| 全画面パス 中央値 | 9,488ms | 3,892ms |
| 全画面パス 最大 | 45,722ms | 5,649ms |

精度も 4B が上だった。8B が `cient_secret` と誤読した箇所を 4B は `client_secret` と
正しく読み、8B が取りこぼしたラベルも抽出している。
